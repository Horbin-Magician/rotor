# 验证、性能与发布验收

返回 [迁移计划](README.md)；功能 ID 见 [功能对照](feature-parity.md)。本文件定义完整验收要求；已执行的 P0 Windows 子集见 [实机证据](evidence/p0-windows.md)，完整跨平台矩阵尚未完成。

2026-09-08 用户调整：本轮专注 Windows，macOS 项暂缓。下文保留完整跨平台要求，暂缓项不填写“通过”；当前 Windows 结果见 [UI 续作核验](evidence/windows-ui-followup.md)。

## 1. 测试环境与证据

Windows x64 和 macOS arm64 均为必测平台；编译成功不能替代本机窗口测试。P0 锁定最低系统版本、Rust/GPUI/组件库版本后，填写实际 OS build、CPU/GPU、驱动、显示器分辨率/布局/DPI 和安装包 hash。

| 环境 | 最低覆盖 |
|---|---|
| Windows | Win10/Win11 中实际承诺的最低版本及当前主测版本；普通/提权启动；集成显卡；单屏/双屏 |
| macOS | arm64，验证候选 macOS 15 及产品最终承诺的最低运行版本；Retina + 外接屏；Spaces/fullscreen |
| 显示配置 | 100%、125%、150%、200% 中至少一种混合组合；副屏左侧/上方负坐标；不同分辨率；拔插和旋转 |
| 用户状态 | 新用户目录、v2.6.0 数据副本、坏记录/缺图、无写权限、无网络、权限拒绝、剪贴板暂时占用 |
| 构建 | 固定 release 依赖；打包后的二进制；发布门槛须使用干净机器，不能借开发机资源路径通过 |

所有会修改配置、贴图、索引或启动项的测试使用临时 profile/虚拟机快照。当前原生壳支持 `--data-dir`/`ROTOR_DATA_DIR`，保留的旧壳源码通过共享核心支持 `ROTOR_DATA_DIR`；未经修改的旧正式安装包不能据此假定支持，仍须用独立系统用户或隔离环境采样。需要区分“保留源码重新构建的旧 UI”和“原始正式产物”的证据。

证据保存在 `doc/gpui-migration/evidence/`，较大的录屏/安装包放 CI artifact 并记录链接与校验和。命名示例 `P5-V10-windows-<commit>.md`；不要提交 API key、真实用户截图或私人路径。可复现的无隐私 UI 输入和生成器位于 `doc/gpui-migration/fixtures/`，贴图进入 GUI 前先执行 `inspect_pins` 只读校验。

## 3. 自动化测试边界

### 3.1 复用现有有价值测试

迁移时保留 config 默认覆盖、排除路径、拼音/别名搜索、索引序列化、索引状态回调、截图 recoverable session、记录保存 generation、剪贴板 change count、DeepSeek SSE 解析、OCR 行合并和缓存中毒恢复测试。

### 3.2 需要新增的行为测试

| 层 | 有价值的测试 |
|---|---|
| runtime | 并发查询/翻译顺序、取消、背压、窗口销毁后的回调、快捷键/配置失败事务 |
| geometry/canvas | 四种坐标转换 round-trip、负坐标、DPI 切换、裁剪边界、zoom 极值、撤销和导出尺寸 |
| raster export | 程序生成的标定图；无缩放几何像素精确比较；文字在固定字体下做容差 golden tests |
| persistence | 旧记录 fixtures、未知键、image_rect 缺省、写入中断、最新代数和恢复幂等性 |
| network | 本地 HTTP/SSE fixtures；UTF-8 跨 chunk、分片/合并 delta、提前 EOF、错误 JSON、请求超时；不调用真实付费服务 |
| UI | 目标 GPUI 版本支持的测试上下文下验证状态/焦点/动作；模拟结果仅覆盖可模拟部分 |
| updater | 本地签名样例、坏签名/长度不符/错误平台、下载中断、安装辅助进程错误和旧包兼容 |

真实窗口层级、系统 IME、权限、剪贴板互通、托盘和安装行为保留本机验收，不用全量 mock 代替。无需给静态文案或简单组件包装编写与实现一一对应的测试。

## 4. 性能测量与目标

### 4.1 统一测量方法

- 对照旧版基线和 GPUI 候选的 release 安装产物，使用同一硬件、系统、电源模式、数据集、窗口数量和图片；关闭调试 overlay/持续日志刷屏。
- 内存必须计入旧版关联 WebView 子进程；记录进程树、private/physical footprint 和 GPU 内存，避免旧版只测 Rust 主进程。两端系统指标名称不相同时分平台比较，不能混为一条曲线。
- 明确“空闲”是索引完成、没有翻译、没有活动动画、没有 OCR 的状态；OCR 热/冷、索引构建分别报告。
- CPU 以一个逻辑核满载为 100%：采样区间进程树 CPU 时间增量 / 墙钟时间；另外可记录系统任务管理器值及其归一化方法。
- 交互时延从 OS 事件/热键接收，到相应内容首帧呈现；查询从提交到第一批结果，翻译 UI 从收到本地 delta 到呈现。另记捕获耗时、纹理上传耗时、OCR 推理耗时，避免把外部网络延迟算成 GUI 回归。
- 普通交互预热 10 次后测至少 100 次，报告 p50/p95；冷启动至少 20 次单列；待机稳定 60 秒后采样 120 秒。长时间常驻至少 2 小时，其中包含连续截图/关闭循环。

### 4.2 初始预算

这些是工程目标，不是测量结果。P0 在固定参考机采集旧版基线并冻结预算；若旧版自身不达绝对目标，记录有依据的目标调整，不能在发布前临时放宽掩盖回归。

| 指标 | 初始目标/验收方式 |
|---|---|
| 稳态托盘待机 CPU | 120 秒平均 ≤ 单逻辑核 0.5%，无固定 60 FPS 重绘/高频空轮询 |
| 搜索/翻译窗口热唤起 p95 | ≤ 150 ms；同时不劣于旧版超过 10%（测量噪声单列） |
| 固定语料搜索首批结果 p95 | ≤ 100 ms；索引未就绪时单列，不掩盖已就绪查询性能 |
| 选区/标注拖动 | 60 Hz 显示器上应用 UI 帧耗时 p95 ≤ 16.7 ms；无持续掉帧和输入积压 |
| 热截图首帧 | 目标比旧版更快；最低要求 p95 不回退超过 10%，分拆捕获与显示耗时 |
| 无贴图、OCR 已释放时的总常驻内存 | 优化目标比旧版进程树低至少 20%；发布最低要求不高于旧版 10%，未达到优化目标须记录原因 |
| 双屏/十贴图峰值内存 | 固定图片条件下不高于旧版 10%；按 RGBA、纹理、窗口、索引分别归因 |
| 资源泄漏 | 20 次预热后做 100 次截图/创建/关闭；最后窗口关闭并等待 OCR 释放，内存增长 ≤ max(10 MiB, 预热后基线 5%)，曲线应进入平台期 |
| OCR/网络 | 同模型输入的 OCR 推理 p95 不回退超过 10%；流式 UI 队列不丢字、不无限增长 |
| 窗口/原生句柄 | 重复循环后回到可解释的基线；句柄数量、强引用和纹理条目不得线性增长 |
| 包体/启动 | 记录包体、安装占用、冷/热启动；初期不凭空承诺 MB 数，发布说明只使用实测值 |

内存泄漏测试允许驱动/分配器保留缓存，但必须同时证明活跃图像/纹理引用数已回落并有稳定平台期。不能仅通过强制清空工作集“满足”内存指标。OCR 空闲释放允许检测调度误差，必须在记录的释放窗口内观察到 pipeline 引用释放。

## 5. 构建与 CI 门槛

根 workspace 和 xtask 已建立，默认原生目标为 `rotor-desktop`。P0 原型仍是 `experiments/gpui-probe` 下的独立 workspace，其结果不能替代当前原生壳的验收。

### P0 原型

```text
cargo check --manifest-path experiments/gpui-probe/Cargo.toml --locked
cargo build --manifest-path experiments/gpui-probe/Cargo.toml --release --locked
```

两端分别运行原型并附本机证据；GPUI 本身的 example 构建不能替代该原型的系统服务集成。

### P1–P8 过渡期

```text
cargo fmt --all -- --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy -p rotor-desktop -p rotor-ui -p rotor-canvas --all-targets --locked -- -D warnings
cargo build -p rotor-desktop --release --locked
yarn build
yarn tauri build
```

上述 Rust 命令在 P1 建立的根 workspace 执行；P1 之前旧 Rust 检查仍在 src-tauri 执行。Windows 和 macOS 各自运行对应平台构建；CI 可以分为核心单测、GPUI 检查、旧壳检查和打包作业，避免每次纯文档更新都打包。

`-D warnings` 首先约束新增 crate；已有 crate 的历史 lint 在 P1 记录基线，按改动范围逐步收敛，不以全面修复无关 lint 扩大迁移范围。OCR 资源测试单独明确所需文件，禁止缺模型时静默跳过仍报告通过。

### P9 最终工程

```text
cargo fmt --all -- --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build -p rotor-desktop --release --locked
cargo tree -p rotor-desktop --edges normal,build
```

当前 xtask 入口如下（路径和版本为参数示意，执行时使用新的独立输出目录）：

```text
cargo run -p xtask -- version
cargo run -p xtask -- set-version <candidate-version> --dry-run
cargo run -p xtask -- build
cargo run -p xtask -- stage <new-stage-directory>
cargo run -p xtask -- verify <stage-directory>
cargo run -p xtask -- package <stage-directory> <new-package-directory>
cargo run -p xtask -- import-profile <source> <new-profile> <new-backup> <source-version>
cargo run -p xtask -- verify-profile <profile-copy-or-backup>
cargo run -p xtask -- sign <artifact>
cargo run -p xtask -- release-manifest <artifacts-directory> <https-base-url> <notes-file> <new-output>
```

正式身份分别用 `build --production` 和 `stage --production <new-stage-directory>`；构建收据、资源和安装身份必须一致。`package` 按执行主机选择平台，不接受 `--target`；`version` 是只读查询，不需要 `--dry-run`。`release-manifest` 仍要求两端已验签、同身份的产物，Windows 单端验证不能作为双平台清单完成或正式通道切换的证据。此处列出可用 CLI，不表示上述安装、签名和发布场景已经执行。

最终应用 normal/build 依赖闭包中不得有 tauri、tauri-runtime、tauri-runtime-wry、tauri-plugin-*、wry、webview2-com、GPUI WebView 组件或 JS 引擎。系统 WebKit 框架如由无关库引入，必须解释实际用途并验证没有 WebView UI 路径；不能只按字符串搜索宣布已去除前端。`tray-icon`/`global-hotkey` 独立库可以保留。

## 6. 更新、安装和恢复演练

1. 保存旧 v2.6.0 安装包、对应签名/元数据和测试数据副本；记录旧包 checksum。
2. 在隔离环境干净安装旧版，创建配置、索引和多张贴图，开启一次自启动后关闭程序。
3. 用测试更新服务或带测试端点的旧客户端等价构建完成候选升级；测试公钥与正式公钥严格分离。另对未经改动的旧安装器/客户端进行可执行的兼容性验收，说明如何让它访问测试产物，不向正式 latest 推送实验包。
4. 验证 GPUI 使用原安装身份、数据目录、资源与权限，并验证后续 GPUI N → N+1。macOS DMG 用于安装交付，更新归档格式按旧客户端实际要求另行生成。
5. 分别注入下载中断、坏签名、解包失败、安装辅助进程失败、UAC 取消、磁盘满；每次确认旧可执行文件和用户数据仍可恢复。
6. Gitee 元数据 URL 重写后，验证产物实际字节和签名对应。两个源有一个不可用时能按既定策略反馈/回退。
7. 在数据副本上用旧版读取 GPUI 写回的配置/贴图；如不兼容，恢复转换与安装回滚必须在同一阶段交付。
8. 试用期间使用独立 prerelease 通道和安装身份。若旧客户端不识别最低 OS 字段，不可仅增加字段后发布不兼容包：验证历史兼容组合、通道分流或旧壳过渡版本。
9. 正式切换后保留可用旧包和恢复说明；不因测试或卸载 GPUI 而移除共享 WebView2 Runtime，不删除用户新截图。

代码回退、安装回退、用户数据回退是三个不同动作。候选发布记录必须分别给出步骤和限制。执行任何回退前退出两个版本，保留当前数据副本；不要用重装程序覆盖丢失截图的问题。
