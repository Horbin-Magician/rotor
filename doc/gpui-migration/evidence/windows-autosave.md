# Windows 设置自动保存续作（2026-09-08）

对应 UI-04 / S04 / V06 / V17。目标是减少普通字段和快捷键保存步骤，同时保留输入、事务与失败反馈；本轮未重新接管桌面。

## 后台合并队列

`Services::save_settings_coalesced` 只合并最后一个尚未被消费的自动批次，同字段保留最新值，批次内各字段共享 SettingsSaved 请求 ID。显式保存会切断合并尾部，之后的自动编辑排到它后面；不能把稍后的输入合并到较早位置，再被旧的显式写入覆盖。

队列由服务持有，已接受的普通字段写入不依赖视图存活。一次自动批次最多 64 个不同字段，验证限制后才修改已接受数据；队列已满但尾部自动批次仍在时，依然能替换该批次的字段值。显式写入失败不会破坏已接受的尾部。

5 项真实 ConfigService/队列测试通过：千次编辑与多字段共享回执、显式保存前后顺序、无视图关闭排空、超限拒绝不改旧值、满队列替换。runtime 严格 clippy 通过。这里的无视图排空测试使用普通字段，不把它当成仍需 UI 协调的全局快捷键退出验收。

## 输入、回执与失败草稿

普通文本及排除目录的已确认修改接入合并队列，输入不等待每次写盘；快捷键录制完成直接提交，手输快捷键在 Enter、离开输入框或窗口失焦时提交。后台同时校验八个已知快捷键，去掉首尾空白；空值允许禁用按键，非法局部键也会令整批事务失败，不再因它不经过全局注册而漏检。

字段模型按本地修订和 OperationId 追踪回执；同一批次可完成多个字段，较旧的成功/失败不能覆盖新输入或掩盖较新的提交失败。规范化结果仅在文本未继续改变、未处于组字时回写；值相同时不重置输入控件或光标。失败保留草稿及“未保存”标记，自动观察不会反复重试同一个失败值，Enter/保存可显式重试。

当前输入引擎的 unmark 操作可能不发 Change，因此只在存在组字标记时进行 100ms 检查，捕捉组字结束；没有组字时不轮询。临时组字文本不写盘。该处理经模型验证，仍需微软拼音实测。

## 关闭和退出

关闭按钮及原生窗口关闭请求会先收集已确认的编辑，等待自动和显式保存回执；失败时保留窗口，允许重试或明确放弃未保存内容。关闭/放弃路径持续屏蔽后续 blur/destruction 观察，防止放弃的草稿又被自动重试。

托盘退出及更新交接通过同一等待路径，主事件循环不再因收到 Quit 命令就提前退出，仍可处理快捷键 Prepare/Finish 确认；等待期间不启动新工具操作。应用退出等待不会被后续普通窗口关闭请求降级。更新安装入口在有待保存、失败或组字内容时禁用，安装开始后锁定设置编辑。

排除目录重建由桌面壳观察成功快照，在最后一次变化 500ms 后合并触发；即使设置页已关闭仍有效，真正退出时取消未执行的重建。保存的数据不依赖该延时任务。

## 检查边界

后台队列增加了快捷键双确认和局部键校验测试，共 7 项专项测试；runtime 全部 30 项测试通过。UI 全部 25 项测试通过，其中字段模型覆盖 UTF-8 组字、手输快捷键确认、共享批次、旧回执、拒绝/重试、规范化以及失败选项不能被其他字段成功掩盖。workspace check 通过，旧 Tauri 仍有三个既有 warning；native/UI/runtime 严格 clippy 及格式检查通过。窗口失焦也会检查已确认编辑，关闭与放弃路径保留观察屏蔽直到视图销毁。

本轮没有重新接管桌面，没有据服务/模型测试关闭 UI-04、IME、真实关闭/退出、更新安装或性能验收。
