## P6 首发标注范围

计划要求首版不新增 redo，但原生工具栏和 Ctrl/Cmd+Shift+Z 曾提供用户级重做。已移除这些额外入口，保留普通撤销按钮和标注模式下的 Ctrl/Cmd+Z。

撤销快捷键现在仅在标注模式接管，Shift/Alt 组合不被当作撤销，非标注模式的组合可继续交给已配置的贴图按键。文字输入已有的 IME/编辑优先分支保留。

文档内部的 redo 保留给渲染/裁剪失败后的事务恢复，因此既有名称包含 redo 的底层测试仍有意义；它不意味着 UI 仍提供重做。14 项 UI 单测、native/UI 严格 clippy 通过，包含新的按键作用域测试及既有失败回滚测试。未将这些测试当作真实 IME 或鼠标验收。

## 保存交互：快捷操作修正与剩余项

旧 QuickSettings 的编辑弹层本来就有保存按钮，原生的编辑保存本身不算增加步骤；但旧启停/删除直接提交，原生此前还需全局保存。

已修正启停/删除：当前列表与已保存数据完全一致且没有打开编辑器时，按稳定 ID 生成更改并直接走既有配置/快捷键事务。界面在事务成功前保留旧行和启停状态，失败时不会先把操作从列表移除。成功保存会收起编辑器。

存在未保存命令、新操作、默认值预览或打开的编辑器时，更改只进入草稿并明确提示保存；不会把其他未确认编辑隐式写入。新增三项规划测试验证干净列表的目标变更、其他草稿隔离、编辑器/新增项及不存在 ID 的边界。17 项 UI 测试通过；最后的编辑器收起改动经严格 clippy 检查。仍需真实 UI 的成功/失败操作验证。

编辑入口展开后改为明确的“取消编辑”：只恢复当前操作的已保存值，未保存的新操作则从草稿移除，其他操作的草稿不被清空；取消同时停止快捷键录制并归还焦点。该控制器改动通过 UI/desktop 严格 clippy，尚未冒充真实点击或焦点测试。

普通文本设置/快捷键的自动保存缺口随后已接入，包含回执、组字和关闭等待，详见[自动保存续作](windows-autosave.md)。UI-04 仍需实际输入、失败和关闭操作验收。

## 贴图失败导出后的目录记忆

无窗口核对发现 `PinView` 将待记忆目录独立存放在视图上：文件导出入队失败或后台导出失败后，该值未清除，随后普通关闭贴图的 Deleted 成功回执也会消费它，错误地写入 `save_path`。这会让一次失败保存影响后续默认目录。

已将目录移入 `PendingFinish`，只随已接受的导出请求保存。入队失败不会留下目录；请求失败时与请求一起丢弃；普通删除请求始终不携带目录。只有对应导出完成成功后才提交目录设置。已有 25 项 UI 测试、native/UI all-targets 严格 clippy 和 workspace 格式检查通过；本问题通过源码状态流核对，未将既有测试标成该鼠标操作的实机回归。真实“保存失败 → 关闭 → 再次保存”的目录及提示验收仍待恢复桌面后执行。

该修复晚于 `fd9b206` 候选，旧候选不包含它；后续实机前需重新构建。
