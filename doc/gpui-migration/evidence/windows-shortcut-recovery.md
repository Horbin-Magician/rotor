# 快捷键回滚失败后的恢复（2026-09-08）

对应 L05 / Q02 / V04 / V07，起点 `5a138cc`。用户要求继续无窗口检查，本轮未创建窗口、注册系统热键或修改真实配置。

## 问题与复现

原 `ShortcutTransaction` 只返回成功添加/移除的事务记录，未逐次更新桌面壳的 `registered` 清单。Prepare 内部回滚失败时，壳仍保留整个旧清单；落盘失败后的 Finish 回滚也先把清单直接赋成旧值。因而实际缺失的旧键被当作存在，实际残留的新键被当作不存在，之后重试的差异计算会漏掉补注册或清理。

先添加故障注入测试：旧键 A 被注销，新键 B 注册成功，新键 C 注册失败，同时恢复 A 也失败。修复前测试确实失败于 `the missing old key must not be advertised as registered`；后端已无按键，壳传入的清单却仍为 A。

## 修复

`ShortcutTransaction::prepare/rollback` 现在接收可变注册清单，每次后端操作成功后才同步添加或删除；失败保留最后已确认状态。桌面壳不再用期望清单覆盖它。重试按该清单计算差异，能恢复缺失键并继续清理残留键；清理仍失败时继续返回错误。

准备失败及落盘失败后的回滚都会刷新事件代次，使旧排队事件失效。动作映射只保留仍已注册的旧键；失败事务残留的新键不会获得未提交的新动作。成功事务仍在落盘成功后切换完整的新动作集合。

## 验证与边界

- 上述修复前失败的测试修复后通过，并验证解除冲突后保存旧配置能够重新注册 A。
- 新增落盘失败后的双重回滚故障测试：B 无法注销、A 无法恢复；准确记录残留 B，清理仍失败时拒绝保存，解除故障后恢复为 A。
- 新增桌面壳纯状态测试：旧事件代次改变、缺失旧键不再参与分发、残留新键不接入新动作。
- `cargo test -p rotor-runtime -p rotor-desktop --offline`：33 + 4 项通过；示例仅编译，未运行。测试链接器输出创建导入库的 `linker_messages` warning。
- `cargo clippy -p rotor-runtime -p rotor-desktop --all-targets --offline -- -D warnings`、workspace 格式及 diff 检查通过。
