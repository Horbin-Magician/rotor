# Rotor 3.1.4

[中文](#中文) · [English](#english)

## 中文

本版本修复 macOS 上非文本窗口的键盘事件路由，改善截图和贴图的 Escape 快捷键响应。

### 修复

- 修复打开设置并激活文本输入后，AppKit 输入上下文可能吞掉截图或贴图窗口 Escape 按键的问题。
- 没有活动文本输入且未处于输入法组词状态的窗口，将按键直接交给 GPUI 处理，使 Escape 可正常取消截图或关闭贴图。
- 文本编辑和输入法组词继续使用原有输入路由，保留 Escape 优先取消组词的行为。

### 发布与验证范围

目标平台为 Windows x64 和 macOS Apple Silicon。发布流程生成 Windows 安装包、macOS DMG、macOS 更新归档及签名更新清单，延续 macOS Developer ID 签名和 Apple 公证流程。

本版本产物需通过发布流水线中的构建、签名、公证与完整性检查。此次键盘修复仍需在 macOS 原生窗口中分别使用英文键盘布局和中文输入法，验证设置输入后取消截图、关闭贴图，以及设置和贴图文本编辑中的组词取消行为。自动化检查不能替代这些原生输入测试，也不代表生产安装升级或完整功能的实机验收。

## English

This release fixes keyboard event routing for non-text windows on macOS, improving Escape handling in capture and pinned-image windows.

### Fixes

- Fix AppKit's input context potentially consuming Escape in capture or pinned-image windows after text input has been activated in settings.
- Dispatch keys directly to GPUI when a window has no active text input and no ongoing IME composition, allowing Escape to cancel capture or close a pin.
- Retain the existing input routing for text editing and IME composition, so Escape can cancel composition before reaching application shortcuts.

### Release and validation scope

Target platforms are Windows x64 and macOS Apple Silicon. The release workflow produces a Windows installer, macOS DMG, macOS updater archive, and signed update metadata, retaining Developer ID signing and Apple notarization for macOS.

This version's artifacts must pass the release pipeline's build, signing, notarization, and integrity checks. The keyboard fix still requires native macOS validation with both an ASCII keyboard layout and a Chinese IME: cancel capture and close a pin after using settings text input, and cancel composition in settings and pin text annotations. Automated checks do not replace these native input tests or establish production installation/update or complete real-device functional acceptance.
