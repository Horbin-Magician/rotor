# 搜索使用记录与排名

Rotor 在搜索结果打开请求被系统成功接受后，记录目标路径、累计次数和最近打开时间。
打开失败、仅选中结果、打开所在目录，以及从设置中打开路径都不计数。
系统接受打开请求不代表目标程序已完成启动或文件已被阅读。

记录保存在当前配置目录的 `search-usage.json`，开发、生产和显式测试目录相互隔离。
最多保留 2,000 个路径；再次写入时淘汰超过 90 天未使用的记录，超量时淘汰最旧记录。
不记录查询词，不读取系统最近使用列表。记录保留未知 JSON 字段，写入使用原子替换。

## 排名影响

排序先比较路径匹配层级，再比较扩展名与使用记录加分。
直接父目录匹配加 128 分；扩展名加分为 exe 10、app/lnk 25。
名称完整匹配、前缀匹配和名称长度均不加分。

使用加分只改变同一路径匹配层级内的顺序：

| 距最近打开 | 最近使用加分 | 频率加分 |
| --- | ---: | --- |
| 不足 1 天 | 24 | `min(4 × floor(log2(次数)), 24)` |
| 1–6 天 | 16 | 同上 |
| 7–29 天 | 8 | 同上 |
| 30–89 天 | 0 | 上述频率加分减半 |
| 90 天及以上 | 0 | 0 |

这些参数是保守的初始产品规则，尚未通过真实使用数据调优。
当天首次成功打开获得 24 分的最近使用加分；64 次起频率加分达到上限。
总使用加分最多 48，扩展名与使用加分合计最多 73，不能越过 128 分的路径匹配边界。
常用的部分匹配可以排在完整或前缀匹配之前，路径限定的优先级不会被使用记录逆转。
旧的高频项目会降权，避免累计次数无限主导排序。

## 分页与性能

一次新搜索固定使用记录快照和时间评分，后续页复用该快照。
各卷在当前索引中验证历史候选的名称、路径及排除规则，将加分候选排序后与原分页流合并。
原分页流过滤已提升的路径，因此后续页的常用项可以进入首页，也不会再次出现。
新请求沿用现有取消机制与请求标识检查；清理或打开操作不使正在翻页的列表跳动。

没有有效使用记录时跳过额外扫描。有记录时，每个新查询增加一次各卷索引扫描，
先过滤名称，只对候选解析路径；追加页不重复扫描。
额外候选缓存受记录数量限制，释放搜索索引时也释放评分快照。
大型索引的首屏延迟仍需实际性能验证，功能测试不能代替性能验收。

## 清理入口

设置 → 搜索 → 使用记录 → **清空使用记录**。
按钮说明清空不可恢复，执行期间禁用重复提交，完成后显示成功或错误。
清理只清空该配置目录的搜索使用记录，保留文件、索引及其他配置；新搜索恢复静态排序。
已经打开的搜索分页继续使用原快照，下一次新搜索生效。

清理持久化成功后才发布新状态。清理前启动但尚未完成的打开操作携带旧代次，
不能把刚清空的记录重新写回；清理后新发起的成功打开正常累计。

## 验证范围

自动化测试使用独立临时目录，覆盖评分上限与衰减、记录容量与过期、重载、未知字段保留、
写入失败、清理后的旧代次拒绝，以及两个索引后端的跨卷分页排序和去重。
Windows 上的便携后端单元测试不代表 macOS 原生运行验收。
